# Ainative 지식 베이스

청크 102개로 이루어진 사내 지식 베이스다. 각 청크는 단일 주제이며 그 자체로 완결돼 있다.

## 어떻게 찾는가 — 3단계

**1. 색인을 먼저 훑는다.** 전문을 읽기 전에 `kb/INDEX.md`에서 후보를 고른다.
한 줄에 한 청크이므로 `grep`이 그대로 걸린다.

```bash
grep -i '<키워드>' kb/INDEX.md
```

키워드는 영어 식별자를 그대로 쓰는 것이 가장 잘 걸린다 — `PreToolUse`, `MCP`,
`SKILL.md`, `RFC 8707`. 한국어 키워드는 어미를 떼고 어간만 쓴다(`설정하는` → `설정`).

**2. 후보 청크 전문을 읽는다.** `kb/chunks/<chunk_id>.md`.
각 청크 frontmatter의 `related_chunks`가 이웃을 가리키므로, 답이 부족하면 1홉만 따라간다.
2홉을 넘으면 정밀도가 떨어진다.

**3. 답에 근거를 붙인다.** 어느 청크에서 왔는지 `chunk_id`로 밝힌다.

## 반드시 지킬 것 — `confidence`

각 청크는 `confidence`를 갖는다. **사실을 단언하기 전에 이 값을 확인한다.**

| 값 | 의미 | 어떻게 다룰 것인가 |
|---|---|---|
| `verified` | 사람이 작성·검증 | 그대로 인용 가능 |
| `auto-merged` | 본문은 사람 작성, 질문은 자동 생성 | 인용 가능 |
| `mixed` | 검증 내용에 **벤더 주장이 섞임** | 사실 확인용으로 인용하지 말 것 |
| `draft` | 신규 집필, **사내 실정 미기입** | 포털 주소·예산·온콜 경로 등이 플레이스홀더다. 사실로 답하지 말 것 |

정본은 `kb/ingestion.yaml`의 `retrieval.filters`다.

## 인용하면 안 되는 것

`kb/corrections.yaml`의 `unverified:` 절에 1차 출처로 확인하지 못한 주장이 있다.
특히 벤더 자체 주장(시장 점유율·다운로드 수)과 2차 출처 기업 도입 수치는
**출처 등급을 밝히지 않고 인용하지 않는다.**

`verified_no_change:` 절에는 확인 결과 원문이 맞았던 항목이 근거와 함께 있다.
가격·토크나이저·캐시 배수를 물으면 여기를 먼저 본다.

## 신선도

청크는 `freshness`(내용 기준 시점)와 `review_by`(재검토 기한)를 갖는다.
기한이 지난 항목을 최신인 것처럼 답하지 않는다. 현재 상태는 아래로 확인한다.

```bash
python3 tools/check_freshness.py
```

## 이 저장소를 고칠 때

`kb/chunks/`, `kb/manifest.jsonl`, `kb/embeddings.jsonl`, `kb/INDEX.md`,
`kb/llms.txt`는 **전부 생성물이다.** 직접 고치면 다음 빌드에서 되돌아간다.
내용을 바꾸려면 `kb/authored/`나 빌더를 고치고 재빌드한다.
사실 정정은 `kb/corrections.yaml`에 1차 출처와 함께 등록한다.

자세한 규칙은 저장소 루트의 `AGENTS.md`에 있다.
