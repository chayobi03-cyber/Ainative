# 사내 정보 기입 요청 — `confidence: draft` 7건

이 문서는 **제가 채울 수 없는 항목**의 목록이다. 사내 환경에만 존재하는 정보라
추측해서 적으면 그럴듯한 오답이 되고, 오답이 RAG에 들어가면 사람이 그대로 따른다.
그래서 빈칸으로 두고 여기에 명시한다.

기입이 끝난 항목은 `kb/authored/<파일>.md`를 고치고 `confidence`를 `draft` → `verified`로
올린 뒤 재빌드한다.

```bash
python3 tools/build_v3.py --v1 <v1> --v23-chunks <v23> --v23-manifest <m> \
  --authored kb/authored --out kb
./tests/run_checks.sh
```

## 1. `v3-onboarding-day1` — 신규 사용자 첫날 경로

**담당 후보**: 플랫폼팀 / 개발생산성팀

| 항목 | 현재 상태 | 필요한 것 |
|---|---|---|
| 패키지 이름 | `corp-mcp-<name>` 플레이스홀더 | 실제 사내 패키지 네임스페이스 |
| 사내 마켓플레이스 주소 | 비어 있음 | `extraKnownMarketplaces`에 넣을 GitHub repo URL |
| 토큰 발급 경로 | "사내 포털" | 실제 포털 URL + 발급 절차 |
| `managed-settings.json` 배포 여부 | 미확인 | IT가 이미 배포 중인지, 아니면 이번에 도입하는지 |
| 온보딩 성공 지표 목표치 | 추정값(30분/1건/1일) | 실측 후 조정 |

**주의**: `curl -sSL https://내부호스트/install.sh | sh` 예시가 본문에 있다. 이 패턴은
문서가 권장하는 PreToolUse guard가 차단하는 대상이다. **사내 install 경로를 allowlist에
등록할지, uvx 경로만 쓸지 먼저 정하고** 그에 맞춰 본문을 정리해야 한다.

## 2. `v3-incident-runbook` — 장애 대응 런북

**담당 후보**: SRE / 운영팀

| 항목 | 현재 상태 | 필요한 것 |
|---|---|---|
| 온콜 연락 경로 | 비어 있음 | 심각도별 호출 대상, 에스컬레이션 순서 |

## 8. 실제 사용자 질의 로그 — 검색 평가의 유일한 빈칸

**담당 후보**: 지식베이스 운영자 / 검색 담당자

`docs/TEST-PLAN.md` §3이 held-out 세트를 필수 보완으로 지정했다. 현재 그 자리는
`tests/heldout_queries.jsonl`의 40건이 채우고 있는데, **이 질의는 사람이 아니라 AI가
지어낸 것이다**(`origin: "llm-authored"`). 실제 질의 분포와 얼마나 다른지 알 수 없다.

| 항목 | 현재 상태 | 필요한 것 |
|---|---|---|
| 실제 사내 질의 로그 | **0건** | 30건 이상. 사람이 실제로 입력한 문장 그대로 |
| 수집 경로 | 미정 | 사내 검색 UI 로그, 헬프데스크 티켓, 팀 채널 질문 중 택일 |
| 개인정보 처리 | 미검토 | 질의문에 이름·프로젝트 코드가 섞이면 마스킹 규칙이 먼저 필요하다 |

**기입 방법.** `tests/heldout_queries.jsonl`과 같은 한 줄 JSON 형식을 쓰되
`origin`을 `"user-log"`로 둔다. 정답 청크는 사람이 지정한다.

```json
{"query": "<사용자가 실제로 친 문장 그대로>", "qrel": {"<chunk_id>": 3},
 "origin": "user-log", "split": "test"}
```

**`split: "test"`가 중요하다.** 기존 40건은 검색 설정을 고르는 데 이미 쓰여서
그 설정의 성능을 편향 없이 잴 수 없다(`docs/TEST-RESULTS.md` §12.8). 실제 로그는
**설정 선택에 한 번도 쓰지 않고** 게이트 전용으로 남겨야 첫 정직한 추정치가 된다.
최적화 하네스(`tools/optimize.py`)는 `test` split을 읽지 않도록 만들어져 있다.

평가기가 `origin`별로 자동 분리 집계하므로 같은 파일에 섞어 넣어도 된다.
**두 출처의 점수를 합산하지 않는 것이 이 설계의 요점이다** — `llm-authored` 점수와
`user-log` 점수의 격차가 곧 "AI가 지어낸 질의가 실제와 얼마나 다른가"의 측정치다.

**왜 급한가.** 현재 held-out 실측이 Recall@10 0.42다(`docs/TEST-RESULTS.md` §12).
이 수치가 실제보다 비관적인지 낙관적인지 판단할 근거가 지금은 없다.
