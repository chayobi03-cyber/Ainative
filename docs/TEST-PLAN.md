# 시험법 (Test Plan) — v3.0 지식 베이스

| 항목 | 내용 |
|---|---|
| 대상 | `kb/chunks/` RAG 청크 세트 및 부속 매니페스트 |
| 도구 | `tools/kb_audit.py`, `tools/make_golden.py`, `tests/run_checks.sh` |
| 실행 환경 | Python 3.11, 외부 네트워크·API 키 불필요 (폐쇄망 CI 가능) |
| 최초 작성 | 2026-08-05 |

## 0. 설계 원칙

**결정론 우선.** 판정은 가능한 한 결정론적 수단으로 한다. LLM judge는 이 계획에 없다 —
청크 세트의 구조적 품질은 전부 계산 가능한 속성이기 때문이다. 내용의 사실성만이
사람 검토를 필요로 하며, 그 부분은 T-11로 분리해 두었다.

**재현 가능.** 모든 시험은 인자 없이 같은 결과를 낸다. 난수·시각·네트워크 의존이 없다.

## 1. 토큰 추정 방법 (T-01의 전제)

### 실물 토크나이저를 쓰지 못한 이유
`tiktoken` 패키지 설치는 성공했으나 `cl100k_base` BPE 파일을 원격에서 받아야 하고,
이 환경의 프록시가 해당 호스트를 403으로 차단했다. `transformers`도 미설치·다운로드 불가였다.

```
ProxyError: HTTPSConnectionPool(host='openaipublic.blob.core.windows.net')
  Tunnel connection failed: 403 Forbidden
```

### 대체 추정식
문자 클래스별 가중합을 쓴다 (`tools/kb_audit.py: estimate_tokens`).

```
tokens ≈ 1.45·(한글 음절 수)
       + 1.00·(기타 CJK 문자 수)
       + 1.30·(ASCII 단어 수)
       + 0.45·(그 외 문자 수)
```

| 가중치 | 근거 |
|---|---|
| 한글 1.45 | UTF-8 3바이트 문자. BPE에서 흔한 음절은 1토큰, 나머지는 2~3토큰으로 갈려 평균이 1.4 부근 |
| ASCII 단어 1.3 | 영어는 단어당 약 1.3토큰이 널리 쓰이는 근사값 |
| 기타 문자 0.45 | 공백·구두점·마크다운 기호는 인접 토큰에 흡수되는 비율이 높음 |

### 이 추정의 한계 — 결과 해석 시 반드시 감안할 것
- **절대값을 신뢰하지 말 것.** 보고되는 모든 토큰 수는 ±20% 밴드를 갖는다.
- **비교에는 유효하다.** 같은 추정식을 모든 세트에 적용했으므로 v1/v2.3/v3 간 **상대 비교**와
  분포 변화 추적은 신뢰할 수 있다. T-01의 판정도 이 상대성에 기대고 있다.
- 코드 블록 비중이 높은 청크는 과소 추정되는 경향이 있다(식별자가 서브워드로 잘게 쪼개짐).
- **네트워크가 열린 환경에서는 실물 토크나이저로 재측정하고 이 절을 갱신할 것.**

## 2. 시험 항목

실행: `python3 tools/kb_audit.py kb/chunks --json out.json`

| ID | 항목 | 판정 기준 | 등급 |
|---|---|---|---|
| **T-01** | 청크 크기 분포 | 800~1500 토큰 범위 밖이 25% 미만 | WARN |
| **T-02** | 청크 자율성 | 선행 문맥 의존 표현("앞 문서", "위에서 설명" 등) 보유 청크 10% 미만 | WARN |
| **T-03** | 메타데이터 완전성 | 필수 5개 필드 누락 0건 | **FAIL** |
| **T-04** | retrieval_questions | 질문 없는 청크 0건 | **FAIL** |
| **T-05** | related_chunks 무결성 | 존재하지 않는 ID 참조·자기참조 0건 | **FAIL** |
| **T-06** | 청크 간 중복 | 5-gram Jaccard ≥ 0.45 쌍 0건 | WARN |
| **T-07** | 카테고리 균형 | 최대 카테고리 점유율 35% 이하 | WARN |
| **T-08** | 포맷 일관성 | 코드 펜스 짝 불일치·H1 누락 0건 | **FAIL** |
| **T-09** | 세트 간 주제 중복 | (비교용, 판정 없음) `--compare` 지정 시 | INFO |
| **T-10** | 병합 보존 불변식 | 입력 조각이 출력에 정확히 1회씩 등장 | **FAIL** |
| **T-11** | 내용 사실성 | 사람 검토 — 자동화 대상 아님 | 수동 |

필수 필드: `chunk_id`, `title`, `category`, `tags`, `retrieval_questions`
권장 필드: `priority`, `confidence`, `freshness`, `related_chunks`, `audience`

### 각 항목의 검출 방법

**T-01** — 본문(frontmatter 제외) 토큰을 추정해 분위수와 범위 이탈 건수를 낸다.

**T-02** — 정규식으로 문맥 의존 표현을 찾는다. 원본 문서가 "앞 문서에서 다룬" 식으로
서로를 참조했기 때문에, 청크로 잘리면 그 참조가 허공을 가리킨다.

**T-03/T-04** — frontmatter를 파싱해 필드 존재와 비어있지 않음을 확인한다.
PyYAML 의존을 피하려고 최소 파서를 직접 구현했다(폐쇄망에서 의존성 설치가 막힐 수 있음).

**T-05** — 전체 `chunk_id` 집합을 만든 뒤 모든 `related_chunks` 참조를 대조한다.

**T-06** — 코드 블록을 제거하고 정규화한 뒤 5-gram 집합의 Jaccard 유사도를 전쌍 비교한다.
코드를 제외하는 이유: 설정 예시가 반복되면 실제 중복이 아닌데도 유사도가 치솟는다.

**T-07** — 카테고리 분포와 최대 점유율. 편중되면 그 카테고리 안에서 검색 변별력이 떨어진다.

**T-08** — ` ``` ` 개수 홀짝, H1 존재. 펜스가 홀수면 청킹이 코드를 잘랐다는 뜻이다.

**T-10** — `tools/build_v3.py`의 병합 루프에 심어 둔 `assert`. 빌드 시 자동 실행된다.
입력 조각 ID 목록과 출력 버킷의 조각 ID 목록이 정확히 일치하는지 검사한다.

**T-11** — 자동화하지 않는다. 인용 수치·버전·URL의 사실성은 공식 문서 대조가 필요하며,
LLM judge로 대체하면 "그럴듯하지만 틀린" 판정을 얻는다. 분기 재검토 시 사람이 표본 검토한다.

## 3. 검색 품질 시험 (T-12, 벡터 DB 적재 후)

적재 전에는 실행할 수 없으므로 절차만 정의한다.

### 골든셋
```bash
python3 tools/make_golden.py kb/manifest.jsonl > tests/golden_retrieval.jsonl
```
각 청크의 `retrieval_questions`가 (질의, 정답 청크) 쌍이 된다.

**출처별로 나누어 집계할 것.** 생성기가 `question_origin`을 남긴다.

| 출처 | 성격 | 해석 |
|---|---|---|
| `v1` | 사람이 작성 | 신뢰도 높음. 주 지표로 사용 |
| `v2.3` | 섹션 템플릿에서 기계 생성 | 본문 어휘와 겹쳐 **점수가 낙관적** |
| `authored` | 갭 청크 집필 시 작성 | 사람 작성이나 표본이 적음 |

### 지표와 목표
| 지표 | 목표 | 비고 |
|---|---|---|
| Recall@10 | ≥ 0.90 | 정답이 후보에 드는가 |
| MRR@10 | ≥ 0.70 | 정답이 위에 오는가 |
| 검색 실패율 | ≤ 3% | 관련 청크 0개 |

### 필수 보완 — held-out 세트
자동 생성 골든셋만으로 판단하면 **자기 어휘로 자기를 찾는 시험**이 된다.
실제 사용자 질의 로그를 30건 이상 모아 별도 세트로 병행 측정하고, 두 점수의 격차를 본다.
격차가 크면 `retrieval_questions`가 실제 질의 분포와 어긋난 것이다.

## 4. 품질 게이트 (CI)

```bash
./tests/run_checks.sh    # 0 = 적재 가능, 1 = 차단
```

| 단계 | 내용 | 차단 여부 |
|---|---|---|
| 1 | T-01~T-08 감사 | T-03/04/05/08 FAIL 시 차단 |
| 2 | 매니페스트 ↔ 청크 파일 ↔ 임베딩 3자 정합 | 차단 |
| 3 | ingestion exclude 경로 실재 확인 | 차단 |
| 4 | 골든셋 생성 가능 | 차단 |
| 5 | `tools/*.py` 컴파일 | 차단 |

WARN 항목(T-01/02/06/07)은 차단하지 않는다. 구조적 결함이 아니라 설계 판단의 영역이며,
기준을 넘겼다는 이유로 빌드를 막으면 기준을 낮추는 압력만 생긴다.

## 6. 이 시험 계획이 다루지 않는 것

정직하게 밝혀 둔다.

- **내용의 사실성** — T-11은 수동이며 이번 빌드에서 전수 검증하지 않았다.
- **실제 검색 성능** — 벡터 DB 미적재 상태라 T-12는 절차만 정의됐고 실행되지 않았다.
- **임베딩 모델 비교** — `bge-m3` 권장은 코퍼스 성격과 폐쇄망 제약에서 도출한 판단이며
  자체 측정 결과가 아니다.
- **한국어 형태소 분석 품질** — 하이브리드 검색 설계에만 반영했고 실측하지 않았다.
