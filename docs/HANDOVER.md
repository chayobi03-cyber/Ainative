## A. 지금 처리하지 않으면 되돌릴 수 없는 것

### A-1. 저장소 자족성 — ✅ 해소됨

`tools/build_v3.py`는 아래 셋을 필수 인자로 요구한다.

```
--v1 <dir>            v1 청크 47개
--v23-chunks <dir>    v2.3 청크 135개
--v23-manifest <file>
```

이전에는 셋 다 저장소에 없었고 개인 Gmail 소유 Google Drive에만 있었다.
접근이 끊기면 재빌드가 영구 불가해지는 상태였다.

**조치 완료** — `kb/_inputs/`에 반입했다(v1 47 + v2.3 135청크, 884KB).
저장소만으로 재빌드해 **바이트 동일 출력**을 재현하는 것을 확인했고,
게이트 4단계가 입력 존재와 개수를 매번 검증한다.

원본 아카이브 SHA256은 `kb/_inputs/README.md`에 기록했다.

**남은 것**
- [ ] Drive 폴더 소유권을 팀 계정/공유 드라이브로 이전 (원본 보존 차원. 재빌드에는 더 이상 불필요)

### A-2. 임베딩 모델 결정에는 락인이 있다

`bge-m3`는 **권장이지 결정이 아니다.** 그리고 한 번 임베딩하면 모델 변경 = 전량 재임베딩이다.

- [ ] 모델 확정 (`kb/chunks/v3-korean-rag.md` 근거 참조)
- [ ] **확정 전에 골든셋으로 2~3개 모델 비교** — 30분이면 끝난다. 나중엔 비싸다
- [ ] 벡터 DB 확정 — `ingestion.yaml`에 기록
- [ ] 결정 근거를 `ingestion.yaml`에 남길 것. 다음 사람이 "왜 이걸 골랐지"를 물어본다

### A-3. 출처·라이선스가 정리되지 않았다

`kb/sources/`의 원본 리서치는 Perplexity 산출물이고, 다수의 외부 블로그·논문을
인용하고 있다. 사내 위키로 재배포할 때:

- [ ] 인용 출처 표기 의무 확인 (법무/보안)
- [ ] 사내 재배포 범위 확인 (전사 공개? 팀 한정?)
- [ ] `unverified` 항목(U-002 FastMCP 점유율, U-003 기업 도입 수치)은
      **1차 출처가 없다.** 사내 규칙·보고서에 인용 금지로 못 박을 것

### A-4. 보안 검토를 받지 않았다

이 KB는 전사 질의 대상이 된다. 아직 아무도 보안 관점에서 보지 않았다.

- [ ] 보안팀 검토 요청
- [ ] 특히 `kb/docs/`의 설정 예시에 실제 사내 호스트명·경로가 없는지 확인
- [ ] 향후 이미지 소스 유입 시 `screened` 정책 실효성 확인 (`kb/schema.md`)

## B. 조용히 무력화되는 것 — 알아야 지킬 수 있다

### B-1. `confidence` 필터는 저장소 밖에서 완성된다

KB는 `confidence` 필드를 제공할 뿐이다. **검색 앱이 실제로 필터를 걸지 않으면**
`draft`·`auto-merged` 청크가 `verified`와 똑같은 얼굴로 답한다.

```yaml
# ingestion.yaml — 이건 설정일 뿐, 앱이 읽어서 적용해야 한다
filters:
  production_default: {confidence: ["verified", "auto-merged"]}
  strict:             {confidence: ["verified"]}
```

- [ ] 검색 앱에 필터 구현 확인
- [ ] 사실 확인이 필요한 질의 경로에 strict 필터 연결
- [ ] **답변 UI에 `confidence` 노출** — 사용자가 초안인지 알아야 한다

### B-2. 골든셋 순환 참조 — 신입이 반드시 밟는다

`tools/eval_retrieval.py`를 기본값으로 돌리면 **Recall@10 = 1.000**이 나온다.
이건 성능이 아니라 누출이다. 질문을 색인에 넣고 그 질문으로 찾은 것이다.

```bash
# 이 수치는 의미 없다
python3 tools/eval_retrieval.py kb/manifest.jsonl tests/golden_retrieval.jsonl

# 유효한 수치는 이것뿐
python3 tools/eval_retrieval.py ... --mode body     # Recall@10 = 0.944
```

- [ ] 인수인계 구두 설명에 이 항목 포함. 문서만으로는 안 읽는다
- [ ] 성능 보고서에 `--mode body` 수치만 쓸 것

### B-3. 두 개의 "역논리" 장치 — 선의로 망가뜨리기 쉽다

**하나. `corrections.yaml`은 적용 0건이면 빌드를 실패시킨다.**
정정 대상이 사라졌는데 원장에 남아 있으면 다음 사람이 "이미 반영됐다"고 오해하기
때문이다. 상류에서 내용을 고친 뒤 빌드가 깨지면 **버그가 아니라 설계다.**
→ 해당 정정 항목을 원장에서 제거하는 것이 정답.

**둘. `tests/fixtures/t13_broken/`은 실패해야 정상이다.**
게이트가 `! python3 tools/kb_audit.py ...`로 **FAIL을 요구**한다.
누군가 "깨진 테스트 데이터"라고 판단해 고치면, T-13은 여전히 PASS하지만
**검사가 작동하는지는 아무도 모르게 된다.**

- [ ] 두 장치의 의도를 인수인계 문서/구두로 전달
- [ ] `tests/fixtures/README` 추가 검토

### B-4. `kb/sources/`를 색인하면 중복 히트가 난다

파생 청크와 원본 전문이 같은 저장소에 있다. `**/*.md`로 적재하면 같은 내용이
두 번 색인되고 검색 순위가 조용히 망가진다. `ingestion.yaml`의 exclude가 유일한 방어선이다.

- [ ] 적재 스크립트가 `ingestion.yaml`을 실제로 읽는지 확인
      (현재 `upload_vectors.py`는 `manifest.jsonl`만 읽으므로 안전. 자체 스크립트를
      만들 때 주의)

## E. 5분 인수인계 — 이것만은 구두로

문서를 다 읽지 않을 사람에게 전달할 4가지.

1. **"`confidence` 필터를 앱이 실제로 걸어야 한다."** 안 걸면 초안이 검증된 답처럼
   나간다. 지금 배포 가능한 건 88개(`verified` 42 + `auto-merged` 46)다. (B-1)
2. **"검색 평가는 `--mode body`로만 해라."** 기본값은 1.000이 나오는데 가짜다. (B-2)
3. **"픽스처 테스트는 실패해야 정상이고, 정정 원장은 다 반영되면 빌드가 깨진다."** 설계다. (B-3)
4. **"구조는 검증됐고 내용은 아니다."** 100청크의 인용 수치는 사실 대조를 거치지
   않았다. 조기 만료 항목만 확인했고 거기서 오류 1건이 나왔다. (`TEST-RESULTS.md` §9)
