# 보안 감사·컴플라이언스 대응 절차

## 한 줄 요약
감사는 **정책 문서가 아니라 증적**을 본다. IBM 조사에서 87%가 "명확한 거버넌스가 있다"고
답했지만 실제 통제를 구현한 곳은 25% 미만이었다 — 그 격차가 감사에서 드러난다.

> **집필 근거**: 원본 리서치는 ISO/IEC 42001, NIST AI RMF, EU AI Act를 참조 프레임워크로
> 언급만 했다. 아래 매핑과 절차는 그 언급을 실행 항목으로 전개한 설계안이며,
> **법적 자문을 대체하지 않는다.** 실제 적용 범위는 법무·보안 부서가 확정해야 한다.

## 감사에서 실제로 요구되는 증적

| 질문 | 필요한 증적 | 어디서 나오는가 |
|---|---|---|
| 누가 무엇을 실행했나 | 툴 호출 로그(사용자·시각·파라미터) | OpenTelemetry 스팬 / 감사로그 |
| 어떤 버전이 돌았나 | 모델·프롬프트·툴 정의 버전 | 버전 pin 기록, 툴 정의 해시 |
| 승인 절차가 있었나 | 승인 이력, 마켓플레이스 등록 기록 | 거버넌스 레지스트리 |
| 위험 작업을 막았나 | 차단 이벤트 로그 | PreToolUse hook exit 2 기록 |
| 데이터가 나갔나 | egress 로그, allowlist 설정 | 네트워크 정책, MCP 게이트웨이 |
| 품질을 검증했나 | 골든셋 실행 이력, pass rate 추이 | CI 회귀 게이트 아티팩트 |

**핵심**: 위 6가지는 사고가 난 뒤에 만들 수 없다. 처음부터 남기지 않으면 감사 시점에 없다.

## 프레임워크 매핑 (실행 항목 수준)

### NIST AI RMF — GOVERN / MAP / MEASURE / MANAGE
| 기능 | 대응 실행 항목 |
|---|---|
| GOVERN | 승인 프로세스, 리스크 비례 심사 등급, 책임자 지정 |
| MAP | MCP 서버·툴 인벤토리, 데이터 접근 범위 문서화 |
| MEASURE | 골든셋 pass rate, tool-call 정확도, 트레이스 보존 |
| MANAGE | 롤백 경로, 사고 대응 런북, 카나리 롤아웃 |

### ISO/IEC 42001 (AI 경영시스템)
문서화·역할·리스크 평가·지속 개선 사이클을 요구한다. 실무적으로는
**"정책 → 통제 → 증적 → 재검토"**가 한 바퀴 돌았음을 보일 수 있어야 한다.
이 저장소의 `review_by` 필드와 분기 재검토가 그 사이클의 최소 구현이다.

### EU AI Act
일반 조항이 2026-08-02부터 적용됐다. 사내 개발 도구가 적용 대상인지 여부는
용도·배포 범위에 따라 다르므로 **법무 확인이 선행되어야 한다.** 이 청크는 판단하지 않는다.

## 감사 대비 상시 체크리스트
- [ ] 감사로그가 **변조 불가** 저장소에 있는가(append-only 또는 외부 전송)
- [ ] 로그 보존 기간이 규정과 일치하는가
- [ ] 툴 정의 서명/해시가 고정되어 rug pull을 탐지할 수 있는가
- [ ] 승인된 서버 allowlist가 실제로 강제되는가(문서만 있는 게 아니라)
- [ ] `managed-settings.json`의 deny 규칙을 하위 스코프가 못 푸는지 실증했는가
- [ ] 최소 권한 스코프 — 와일드카드(`*`, `all`, `full-access`)가 없는가
- [ ] 의존성 CVE 스캔이 CI에 있는가(mcp-remote 유형 취약점)
- [ ] 개인정보가 프롬프트·로그에 들어가지 않는지 샘플 검증했는가

## 감사 요청이 들어왔을 때 (7일 시나리오)
1. **1일차** — 범위 확정. 어떤 시스템·기간·데이터가 대상인지 문서로 받는다.
2. **2~3일차** — 위 6가지 증적을 기간별로 추출한다. 자동 추출이 안 되면 그 자체가 발견사항이다.
3. **4일차** — 갭 목록화. 없는 증적을 숨기지 않는다. 없는 이유와 보완 계획을 쓴다.
4. **5~6일차** — 통제 실효성 실증. 정책 문서가 아니라 **차단이 실제로 일어난 로그**를 보인다.
5. **7일차** — 개선 계획 제출. 기한과 책임자를 명시한다.

## 자주 나오는 지적
- "정책은 있는데 강제가 없다" — hook·managed settings로 강제하고 그 로그를 보인다.
- "누가 승인했는지 모른다" — 승인 이력이 사람 기억에만 있으면 증적이 아니다.
- "모델이 알아서 거른다고 가정했다" — 원본 리서치의 MCPTox 벤치는 최강 방어 모델조차
  거부율 3% 미만임을 보고한다. 모델 판단을 통제로 계상하지 않는다.
