# 한국어 RAG 고려사항 — 임베딩 선택과 토큰 예산

## 한 줄 요약
이 KB는 **한국어 서술 + 영어 기술용어** 혼용체다. 이 조합에서는 영어 중심 임베딩의
기본 선택이 최선이 아니며, 폐쇄망 제약까지 감안하면 **bge-m3가 기본값**으로 적합하다.

## 왜 기본값을 바꿔야 하는가
원본 v2.3의 임베딩 가이드는 OpenAI `text-embedding-3-small`을 한국어 "무난"으로 표기하고
사실상 기본 경로로 제시한다. 그러나 이 코퍼스의 실제 성격은 다음과 같다.

- 서술·설명은 한국어
- 식별자는 영어 그대로 — `PreToolUse`, `Streamable HTTP`, `RFC 8707`, `cache_control`
- 표·코드 블록 비중이 높음

즉 **질의도 혼용으로 들어온다**("PreToolUse 훅 차단 어떻게 해?"). 한국어 의미 파악과
영어 식별자 보존을 동시에 해야 하므로 다국어 특화 모델이 유리하다.

## 모델 선택표

| 모델 | 차원 | 한국어 | 폐쇄망 | 비용 | 권장 |
|---|---|---|---|---|---|
| **BAAI/bge-m3** | 1024 | 우수 | ✅ 로컬 | 무료 | **기본값** |
| Cohere embed-multilingual-v3.0 | 1024 | 우수 | ✗ API | 유료 | 외부 API 허용 시 |
| OpenAI text-embedding-3-large | 3072 | 무난 | ✗ API | 유료 | 이미 OpenAI 스택인 경우 |
| OpenAI text-embedding-3-small | 1536 | 무난 | ✗ API | 저렴 | 비권장 — 기본값으로 부적합 |

**bge-m3를 기본값으로 두는 이유 3가지**
1. 폐쇄망에서 그대로 돈다 — 업로드 불가 제약 환경에서 API 임베딩은 애초에 선택지가 아니다.
2. 무료이므로 재임베딩 비용이 0이다. 청크를 자주 고치는 초기에 이게 크다.
3. dense·sparse·multi-vector를 함께 내므로 하이브리드 검색 구성이 단순해진다.

> **검증 필요**: 위 "우수/무난" 등급은 원본 v2.3 가이드의 표기를 따른 것이며 자체 측정이
> 아니다. 도입 전 이 KB의 골든셋으로 Recall@10을 직접 비교하라. 모델 비교는 30분이면 끝난다.

## 토큰 예산 — 한국어는 비싸다
같은 내용이라도 한국어는 영어보다 토큰을 더 쓴다. 이 저장소의 추정기
(`tools/kb_audit.py`)는 한글 1음절을 약 1.45토큰으로 계산한다.

**실무적 함의**
- 청크 크기 800~1500 토큰은 한국어 기준 대략 **550~1000자** 수준이다. 영어 감각으로
  "짧다"고 느껴도 토큰 예산은 이미 찼을 수 있다.
- 컨텍스트에 청크 5개를 넣으면 4,000~7,500 토큰이다. 리랭킹으로 3~5개만 넣는 이유가 여기 있다.
- 모델 업그레이드로 토크나이저가 바뀌면 한국어 쪽 증가폭이 더 클 수 있다. 예산 재계산 시
  영어 기준 비율을 그대로 적용하지 않는다.

## 하이브리드 검색에서의 한국어 처리
BM25를 붙일 때 **형태소 분석기 없이 공백 토큰화만 쓰면 한국어 재현율이 떨어진다.**
"차단하는", "차단을", "차단이"가 서로 다른 토큰이 되기 때문이다.

선택지:
- **간단**: `retrieval_questions`와 `tags`에만 BM25를 걸어 어미 변화 영향을 줄인다(이 KB의 기본).
- **정석**: 형태소 분석기(Kiwi, Mecab-ko 등)로 명사만 추출해 색인한다.
- **절충**: 영어 식별자는 BM25, 한국어 서술은 dense에 맡기는 이원 구성.

영어 식별자는 어미 변화가 없으므로 BM25가 잘 듣는다 — 그래서 혼용 코퍼스에서
하이브리드가 특히 효과적이다.

## 청크 작성 시 한국어 규칙
- 한 문단 3~5문장 이내. 긴 문단은 임베딩에서 의미가 희석된다.
- 영어 식별자는 **번역하지 않고 원문 그대로** 둔다. `PreToolUse`를 "사전 도구 사용"으로
  옮기면 검색이 안 된다.
- 제목에 핵심 명사를 넣는다. 제목은 임베딩 텍스트 앞머리에 오므로 가중치가 높다.
- 표의 헤더는 한국어, 값의 식별자는 영어 — 이 KB의 관행이며 양쪽 질의를 모두 받는다.

## 주의
- 한국어 임베딩 벤치마크는 공개 자료가 영어보다 얇고 편차가 크다. 벤더 표기를
  그대로 믿지 말고 **자체 골든셋 측정**으로 결정한다.
- 다지역 배포 계획이 없다면 다국어 모델의 나머지 언어 성능은 고려하지 않아도 된다.
  선택 기준은 "한국어+영어 혼용" 단일 축이다.
