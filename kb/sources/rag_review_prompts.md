# RAG 추가 계획 및 설계 팁 점검 프롬프트

> 아래 프롬프트를 AI 어시스턴트(Claude, Gemini, ChatGPT 등)에 복사·붙여넣어,
> 현재 RAG 청크 세트의 설계 품질과 누락된 영역을 점검합니다.

---

## 프롬프트 A: 청크 설계 품질 점검

```
당신은 RAG 시스템 아키텍트입니다. 첨부된 RAG 청크 파일들과 매니페스트를 검토하고
다음 기준으로 설계 품질을 평가해 주세요.

[평가 기준]
1. 청크 크기: 각 청크가 800~1500 토큰 범위인가? (너무 짧거나 긴 청크 식별)
2. 자율성: 각 청크가 다른 청크 없이도 독립적으로 이해 가능한가?
3. 메타데이터 완전성: YAML frontmatter의 모든 필드가 채워져 있는가?
4. retrieval_questions: 실제 사용자 질문과 매칭될 가능성이 높은가?
5. related_chunks: 청크 간 연결이 의미적으로 적절한가?
6. 중복성: 청크 간 내용 중복이 있는가?
7. 커버리지: 원본 문서의 핵심 정보가 빠짐없이 청크화되었는가?
8. 카테고리 분균형: 특정 카테고리에 청크가 과도하게 편중되어 있지 않은가?

출력 형식:
- 각 기준별 평가 (통과/경고/실패 + 사유)
- 개선 권장 사항 목록 (우선순위 순)
- 누락된 청크 주제 제안 (있는 경우)
```

## 프롬프트 B: 누락 영역 탐지

```
다음은 사내 AI 협업용 툴 생성 에이전트 운영 표준을 위한 RAG 청크 목록입니다.
47개 청크가 다음 카테고리로 분류되어 있습니다:

- specification (MCP 사양, 전송, SDK)
- best-practices (Anthropic 툴 가이드, Skills)
- quality (Inspector, eval, compliance)
- security (보안 통제, CVE)
- architecture (워크플로우, 프레임워크 비교)
- evaluation (평가 방법론, 회귀 게이트, 관측)
- governance (배포, 거버넌스, 채택)
- development (Hooks, git worktree, AGENTS.md, 개발 규칙)
- operations (로드맵, Quick Wins, 체크리스트, FAQ)
- cost (caching, ccusage, 모델 라우팅)
- reference (설정 파일, 프롬프트 템플릿)

질문: 이 청크 세트에 누락된 주제나 추가해야 할 청크가 있는지 검토해 주세요.
특히 다음 관점에서 확인해 주세요:

1. 신규 사용자 온보딩에 필요한 정보가 충분한가?
2. 에러 트러블슈팅/디버깅 가이드가 포함되어 있는가?
3. 버전 마이그레이션 가이드가 있는가?
4. 엣지 케이스와 알려진 제한사항이 문서화되어 있는가?
5. 실제 운영 시나리오(장애 복구, 스케일링, 모니터링 알림)가 커버되는가?
6. 보안 감사/컴플라이언스 대응 절차가 있는가?
7. 비용 예산 책정과 한도 관리 가이드가 있는가?
8. 다국어/다지역 고려사항이 있는가?

누락된 각 항목에 대해:
- 제안 청크 ID (rag-{topic}-001 형식)
- 제목
- 카테고리
- 우선순위 (high/medium/low)
- 예상 내용 요약 (3~5문장)
```

## 프롬프트 C: RAG 파이프라인 통합 설계 점검

```
당신은 엔터프라이즈 RAG 시스템 설계자입니다. 다음 RAG 청크 세트를
벡터 DB에 적재하고 검색 파이프라인을 구축하려고 합니다.

청크 특성:
- 총 47개 청크, 한국어, 마크다운 포맷
- YAML frontmatter에 메타데이터 포함 (chunk_id, category, tags, priority,
  retrieval_questions, related_chunks 등)
- 카테고리: specification, security, development, evaluation, governance,
  cost, operations, reference 등

다음 설계 결정을 검토하고 권장사항을 제시해 주세요:

1. 임베딩 모델 선택:
   - 한국어+영어 혼용 텍스트에 적합한 임베딩 모델은?
   - 로컬(폐쇄망) vs API 호출 시 각각의 권장 모델은?

2. 청킹 전략:
   - 현재 청크 크기가 적절한가? (평균 토큰 수 확인 필요)
   - YAML frontmatter를 청크 내용에 포함해야 하는가, 메타데이터로 분리해야 하는가?
   - 코드 블록이 청크를 분할하는 문제는 없는가?

3. 메타데이터 필터링:
   - category, tags, priority, audience를 프리필터로 사용하는 전략이 적절한가?
   - 사용자 역할(개발자/운영자/보안담당자)별 필터링 설계

4. 검색 품질 최적화:
   - retrieval_questions를 하이브리드 검색(BM25 + 벡터) 보조 텍스트로 활용하는 방안
   - related_chunks를 이용한 컨텍스트 확장(자식→부모 청크 검색) 설계
   - 리랭킹(reranking) 전략 권장사항

5. 평가 지표:
   - RAG 시스템의 검색 품질을 어떻게 측정할 것인가? (Recall@k, MRR, NDCG 등)
   - golden test set을 어떻게 구축할 것인가?

6. 운영 고려사항:
   - 청크 업데이트 시 증분 인덱싱 전략
   - 버전 관리 (청크 ID + freshness 필드 활용)
   - 모니터링 지표 (검색 실패율, 클릭스루율, 피드백 수집)
```

## 프롬프트 D: 청크 내용 품질 심층 검토

```
첨부된 RAG 청크 파일 중 무작위로 5개를 선택하여 다음 기준으로 심층 검토해 주세요.

[검토 항목]
1. 사실 정확성: 기술적 주장이 공식 문서/신뢰 가능 출처와 일치하는가?
2. 최신성: 인용된 버전 번호, 날짜, 링크가 현재 시점에서 유효한가?
3. 완전성: 핵심 정보가 누락 없이 포함되어 있는가?
4. 명확성: 전문 용어가 적절히 설명되어 있는가?
5. 실행 가능성: 검색 후 실제 행동으로 이어질 수 있는 구체적 지침이 있는가?
6. 출처 표기: 인라인 링크가 포함되어 있는가?
7. 포맷 일관성: 다른 청크와 동일한 구조(한 줄 요약 → 핵심 내용 → 체크리스트)를 따르는가?

각 청크별로:
- 검토 결과 요약 (통과/수정 필요)
- 발견된 이슈 목록 (있는 경우)
- 구체적 수정 제안 (있는 경우)
```

## 사용 방법

1. **프롬프트 A** → 전체 청크 세트의 구조적 품질 점검 (가장 먼저 실행 권장)
2. **프롬프트 B** → 주제 커버리지 갭 분석 (누락된 청크 식별)
3. **프롬프트 C** → RAG 파이프라인 설계 검토 (벡터 DB 적재 전)
4. **프롬프트 D** → 개별 청크 내용 품질 심층 검토 (정기 품질 감사용)

각 프롬프트 실행 시 `rag_chunks/` 폴더의 청크 파일과 `rag_manifest.json`을 함께 제공하면 됩니다.
